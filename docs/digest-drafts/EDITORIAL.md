# 每日论文资讯的编辑目标

用户的目标是每天了解值得关注的新论文，并判断近期领域进展、工作新意与阅读优先级。用户已明确选择“领域进展”，研究机会和技术落地作为次要信息。前台采用资讯简报；精读证据留在底稿。

## 每日选稿（2026-10-27以价值判断取代数量限制）

每天对论文、技术资讯和社交材料先筛选再写作。不设入选篇数、重点篇数、最低数量或淘汰比例；即使很多条都重要，也不为减少数量而删掉。重点关注AIOps、Ops4LLM、AgentOps、混沌工程和系统可靠性与优化，同时保留有明确迁移价值的邻近领域工作。

每个判断要说明具体问题、独有贡献、原始证据以及值得关注的原因。新方法、新问题、可靠测量、负面结果、真实事故和深入工业经验都可能重要，不以SOTA、作者名气、机构或开源状态代替判断。同题工作比较机制和证据后再去重；“重复”要有具体对比对象，产品公告含实质信息时也可选。

区分deep_read（重点）、brief（简述）、exclude（有依据的取舍）、needs_evidence（待核验）和pending_capacity（资源不足未完成）。是否收录与写多长分开，不把未入选项放进延伸阅读。缺乏全文、证据不明或处理不完不能冒充“没有价值”。每条候选在内部selection保留relevance/contribution/evidence_status/reason，中英入选集合与详略一致；未入选均留deferred记录，不静默丢弃。

本规则优先于下文历史样稿中的固定篇数。正常日更沿用2026-10-22验证后自动提交发布授权，不追溯删改已发表文章；早期草稿未启用/不发布描述不再限制每日流程。

## 每期回答的问题

1. 今天或本期有什么值得关注的工作？先给少量重点，不平均分配篇幅。
2. 它研究的具体问题是什么，与已有常见做法相比改了什么？不未经检索宣称首次。
3. 关键结果说明了什么？只保留影响阅读判断的数字及必要条件。
4. 这项工作在 AgentOps、AIOps 和系统可靠性领域推进了什么，证据到了什么程度？不为每篇硬接选题建议，不凭六篇样稿推断整个领域趋势。
5. 值不值得读原文，优先看哪部分？给出理由。

## 表达与来源

- 用短中文观点标题帮助浏览，保留英文原题与原文链接。
- 少写页码、图号、审核流程与逐条方法学批评。详细定位、版本、图源和核对记录放在内部底稿。
- 图只在帮助理解核心新意时出现；图注解释机制，不重复“来源：原文图 X，PDF 第 Y 页”。
- 每篇不必强行套相同长度和标题。重点论文说明问题、机制、证据和研究关联，其余快速交代。
- 各条来源保留实际发布日期，旧论文不能称为当天首次发布。选稿时间窗口、时区核对和清单覆盖记录留在内部底稿，不在前台另写批次说明。
- 真正每天选稿时需要先检索指定时间窗口的来源、去重，再读重点论文原文；没有完成检索，不声称覆盖了当天进展。
- 未启用定时任务。稿件保持 publish:false，由用户确认文风及内容后再接入正式栏目。

## 用户确认的详略结构（2026-10-18）

采用 The Batch 的资讯叙事顺序，并借鉴 The Morning Paper 对设计与运行过程的解释深度。结构是：200–300 字本期总览，2 篇约 800–1200 字重点解读，其余约 200–400 字研究动态。问题清单用于内部检查，不强制把八个问题都变成前台标题。

重点论文回答：具体问题；已有做法与不足；关键新意；输入/过程/输出；相对基线的效果与成本；适用范围；在领域中的位置；进一步阅读及资源入口。增加篇幅主要用于背景、新意、运行过程和结果解释，不恢复密集页码或逐篇研究选题建议。

标题约定（用户明确纠正）：每日一期必须以日期领头，采用“YYYY年M月D日｜本期主题”。日期表示期次/阅读批次，不能用改稿日期冒充论文新鲜度。论文小标题用方法名＋具体贡献，英文原题和链接保留。首屏给出重点入选理由，正文说明与最接近工作的区别，阅读判断区分实证研究、方法改进、可行性验证、工业实践和早期探索。每图保留中文读图顺序与可见的原图入口。

用户新增明确要求（2026-10-19）：以后 Paper Digest 与 Tech Notes 新增或修改时，中英文必须在同一批次完成并更新。标题、摘要、正文、图注/alt、表格、列表和各语言搜索同步；先检查配对与切换，再更新预览。不能先发布中文、等用户发现后再补英文。英文原题保留，译文来源如实记录；原有缺译回退测试继续保留，仅作为健壮性保护。

## 2026-11-18：基于 171 项人工审阅的正负面选稿细则

2026-11-15 至 2026-11-17 完成对既有 `171` 项已发布条目的逐条审核与台账复盘（保留并以一手源重写 `68` 项 / 撤除 `103` 项；其中 Tech Notes 留 `32` 撤 `32`，Paper Digest 留 `35` 撤 `50` 篇及 `1` 期空壳日报，社区动态仅留 `1` 撤 `20`）。为沉淀一致的过滤与写作准绳，补充以下正负面细则：

### 五类正向保留边界（勿因体裁或缺少开源仓库误杀）

1. **一线基座模型发布与服务定价/路由报告**：即使未公开系统源码，只要包含推理 effort 与缓存成本曲线、轨迹内多模型切换、长程 SWE/安全评测口径、安全分类器回退或评测感知审计细节（如 *Gemini 4 Carbon / Hydrogen*、*Claude Opus 5.5 / Fable & Mythos 5.2*、*Kimi K3.1 Pro*），均直接服务于 AgentOps 与推理架构选型，保留并基于一手页深挖边界。
2. **多模态生成与端侧推理加速**：落在推理流水线、资源与精度协同调度、内核优化或真机实测可行性搜索与回滚门控的工作（如 *FastVideo Pika H3*、*Mobile AI Factory*）纳入范围；排除桌面端精度不等价的单机演示或纯图像扩散静态编译。
3. **Computer Use（CUA）/ GUI Agent 的筛选分水岭**：优先保留关注混合执行接口（CLI/代码/语义树/GUI 协同）、evolved harness 或性能优化的系统工作（如 *Hybrid Computer Use*、*Mage-VL-Cowork*）；排除纯通用经验合成训练报告或仿制网页 RL 轨迹扩展工作（如 *NorthCUA*、*WebHarbor*）。
4. **形式化验证与证明系统**：优先保留面向真实分布式系统或数据库规约（如 *TLAPS-Bench*、*GenDB-V*）、推动程序修复的结构化反例诊断（如 *TopoVerus*）、验证器假阳性与空洞规约剖析（如 *Verified but Vacuous*）以及可迁移至长程 Agent 的共享搜索图（如 *LEAP*、*LeanDojo-v2*）；排除纯数学/语言证明脚本修补或高开销 zkVM 编译器研究。
5. **工业界工程复盘与原创 X 长文**：只要提供可复用的生产 Harness 演进、追踪链路、自适应遥测、缓存感知路由、静默退化排查链或系统化故障测试/评测框架（如 *incident.io AI SRE*、*Sentry Agent Tracing*、*Grafana Knowledge Graph / Adaptive Telemetry*、*llama.cpp 量化 KV 静默回退*、*MASA 无人值守 Agent 故障实验*、*OpenRouter Auto Router*），即便缺少传统学术对比表也可保留，并如实写明证据边界。

### 六类明确排除（`exclude`）与缓审（`needs_evidence`）准则

1. **偏离 `AI4SRE / SRE4AI` 主线**：排除传统广告检索/推荐训练与漏斗算力、主机内核提权/并发 Fuzzing、高开销已弃坑 zkSNARK/FHE 推理、纯安全合规政策、纯静态 IR/RAG、纯 RL 样本调度与大模型训练显存重算（勿误标为 Agent 轨迹压缩）、离线微架构模拟器与定制 NMP 芯片仿真、DSP/RISC-V 局部向量化、无线丢包 FEC、气象 HPC、3DGS 渲染、嵌入式微内核及传统金融/土木/民航停飞行政通报。
2. **黑盒厂商通稿与系列导言半成品**：排除仅宣布 GA/Private Preview 或展示产品概念图、未公开核心算法、阈值、误报/漏报率或 MTTR 实测的厂商宣传稿；排除实验留待下篇的 Part-1 导言及常规千行硬件后端胶水适配笔记。
3. **社交短讯严进**：社区短讯仅 `4.8%` 通过审阅。除完整原创 X Article 或补齐权威一手评测报告（如 *Forbes* 实测披露的 *1Password × Mercor*）外，缺乏硬件/长度分布/尾延迟/对照基线的峰值吞吐与 TCO 喜报、Day-0 支持短讯、竞赛排名、个人轶事、高管口播访谈及二手论文摘抄一律不收。
4. **站内重复、微小补丁与空壳日报**：已有或同批已选独立 Tech Note 时，不再在日报社区动态中重复摘要或跨日回指；底层机制已被架构专篇覆盖的微版本补丁或早期 Beta 预告不保留；同日高度同质论文比较机制与实测后只留代表作；无入选论文绝不构造零论文日报空壳。
5. **伪系统实验与旧作重传**：排除宣称服务优化却仅测 `batch=1`、用小模型训练配合大假权重模拟显存、极窄玩具样本或无实验空泛倡议（底层抽象极具突破性时须显式披露样本边界）；严格核对首发年份与会议录用史，拦截旧年论文重传或旧文综述回锅（arXiv 新版撤回但 `v1` 完整有效时，可依 `v1` 审读并注明版本撤回状态）。
6. **抓取受阻先入 `needs_evidence`，绝不靠常识注水**：遇到源站 `403`、付费墙、空壳页或早期状态页简讯导致正文缺失时，必须进入 `deferred (needs_evidence)` 等待补证，严禁凭摘要或假设系统与教科书公式凑成独立长文；凡正式保留条目均应回读完整一手原文并核对双语主题标签收敛。
