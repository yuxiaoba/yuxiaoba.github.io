# 每日论文资讯的编辑目标

用户的目标是每天了解值得关注的新论文，并判断近期领域进展、工作新意与阅读优先级。用户已明确选择“领域进展”，研究机会和技术落地作为次要信息。前台采用资讯简报；精读证据留在底稿。

## 每期回答的问题

1. 今天或本期有什么值得关注的工作？先给少量重点，不平均分配篇幅。
2. 它研究的具体问题是什么，与已有常见做法相比改了什么？不未经检索宣称首次。
3. 关键结果说明了什么？只保留影响阅读判断的数字及必要条件。
4. 这项工作在 AgentOps、AIOps 和系统可靠性领域推进了什么，证据到了什么程度？不为每篇硬接选题建议，不凭六篇样稿推断整个领域趋势。
5. 值不值得读原文，优先看哪部分？给出理由。

## 表达与来源

- 用短中文观点标题帮助浏览，保留英文原题与原文链接。
- 少写页码、图号、审核流程与逐条方法学批评。详细定位、版本、图源和核对记录放在内部底稿。
- 图只在帮助理解核心新意时出现；图注解释机制，不重复“来源：原文图 X，PDF 第 Y 页”。
- 每篇不必强行套相同长度和标题。重点论文说明问题、机制、证据和研究关联，其余快速交代。
- 各条来源保留实际发布日期，旧论文不能称为当天首次发布。选稿时间窗口、时区核对和清单覆盖记录留在内部底稿，不在前台另写批次说明。
- 真正每天选稿时需要先检索指定时间窗口的来源、去重，再读重点论文原文；没有完成检索，不声称覆盖了当天进展。
- 未启用定时任务。稿件保持 publish:false，由用户确认文风及内容后再接入正式栏目。

当前样稿沿用 2026-10-07 至 2026-10-11 的六篇，以用户明确的“领域进展”为目的，突出近期变化、值得关注的工作和后续跟踪方向；不默认用户在寻找研究选题。

采用 The Batch 的资讯叙事顺序，并借鉴 The Morning Paper 对设计与运行过程的解释深度。结构是：200–300 字本期总览，2 篇约 800–1200 字重点解读，其余约 200–400 字研究动态。问题清单用于内部检查，不强制把八个问题都变成前台标题。
